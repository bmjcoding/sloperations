## Most consequential findings

1. Agent consumption is already in the market. Greptile, CodeRabbit, Qodo and Bugbot document agent workflows; a finite iteration cap alone does not bound API spending or patch scope. [Greptile skills](https://www.greptile.com/docs/mcp/skills), [Qodo fix loops](https://docs.qodo.ai/code-review/optimize-review-focus-in-fix-loops), [Bugbot](https://cursor.com/docs/bugbot).
2. Make the reviewer read-only for code and let the author's coding agent repair verified findings. The coordinator owns attempts, leases, scope, total budgets, and terminal states.
3. Shift left by distributing the same executable rules locally and on the server. Use architecture/types/tests for recurring errors; reserve semantic inference for contextual bugs. [Lauren's original post](https://x.com/poteto/status/2111133080526495985), [pstack correct](https://github.com/cursor/plugins/blob/main/pstack/skills/correct/SKILL.md).
4. Target a measured small-PR fast path; do not promise exhaustive review in seconds. Bedrock schema compilation can add about 90 seconds on a new schema, so stable schemas/prewarming belong outside the critical path. [Bedrock structured output](https://docs.aws.amazon.com/bedrock/latest/userguide/structured-output.html).
5. Code Insights failure is not automatically a merge gate. Enforce required checks separately, and ensure they represent the reviewed source/destination pair. [Atlassian](https://developer.atlassian.com/server/bitbucket/how-tos/code-insights/).
